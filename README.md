# BULK ONE

Notionの「画面一覧・画面遷移」と19個の子ページをもとにした、Expo SDK 58 / Expo RouterのモバイルUIです。

## 起動

Node.js 22.13以上（対応LTS推奨）が必要です。標準のNode.js 20ではSDK 58の一部ツールが動作しません。

```sh
npm install
npm start
# Webで確認する場合
npm run web
```

「はじめる」からメールアドレスの形式を満たすデモ値を入力し、確認コード `123456` と8文字以上のデモパスワードで進めます。実際のメールやパスワードは不要です。

通常利用はホーム・運動・食事・進捗・設定の5タブです。新規登録後はプロフィール→目標→ホームの順に進みます。S-012の条件入力→生成→プレビュー→明示的承認は、初めて運動を開始するとき、またはプラン変更時に行います。プラン未作成でも、基本情報と目標の入力完了後はホーム・食事・体組成の記録を利用できます。未承認のプランを運動メニューとして表示せず、変更案を中断した場合は既存の承認済みプランを保持します。

子ページ本文の修正済み仕様を優先しています。S-010の目標入力はS-011に集約し、S-030は記録メニュー、S-031は運動記録としました。水分・睡眠・写真解析などの将来機能は準備中です。

## デモの範囲

料理の選択欄を押すと `/meals/dish-search`（料理検索画面）へ進み、料理名を検索して複数選択できます。「選択した料理を反映する」で元の入力画面へ戻ります。検索を中断した場合は元の選択を保持します。カメラの撮影・撮り直し・写真削除はカロリー・PFC入力ステップの上部だけに配置し、食事区分・日時設定、料理検索、確認・保存完了の各画面には撮影ボタンを表示しません。

食事記録は自由な食事名入力から、仮の料理一覧の複数選択に変更しています。料理DBは未接続で、カロリー・PFCは手入力です。画面上部の「写真を撮る」はExpo ImagePickerでOSのカメラ画面を開きます。撮影した写真はプレビュー・撮り直し・添付解除ができ、保存した食事の詳細にも表示します。写真のURLは起動中の記録と下書きに保持し、クラウドへのアップロード・写真からの栄養解析は行いません。端末キャッシュの写真なので永続保存は保証しません。権限拒否・撮影キャンセルでも既存の入力内容を保持します。

カメラ権限の説明文を`app.json`で設定しています。権限設定を反映するにはアプリバイナリの再ビルドが必要です。Webではブラウザ・端末によって撮影またはファイル選択の画面になります。カメラ撮影は実機で確認してください。

- 認証、メール送信、Cognito、AI/Bedrock、バックエンドAPIは未接続です。
- プランとレビュー文章は固定のUIサンプルです。実データに基づくAI提案とは表示を分けています。
- 記録の追加・編集・削除・集計と入力途中の保持はメモリ内で動作します。再起動・リロードで消えます。
- 未入力の任意栄養値や体脂肪率は未記録として扱います。未記録日を0として平均しません。
- プラン承認時の設定はスナップショットとして保持し、その後の設定編集で上書きされません。
- ヘルスケアの全ステップはUIプレビューです。OS権限、同期、実データ取得は行いません。Androidは正式仕様どおりHealth Connect表記です。
- 記録削除・退会はデモ内の状態だけをリセットします。本番の削除完了を示すものではありません。
- モック内の写真やキャラクターは権利・元画像が未確定のため、共通アイコンを使っています。

## 検証

```sh
npm run typecheck
npm run lint
npx expo export --platform web
npm run test:e2e
```

E2EはWebビルドを静的プレビューし、EdgeのiPhoneサイズで初回設定・記録・レビューなどを検証します。Microsoft Edgeが必要です。実機のiOS/Android、OS権限や本番API接続の検証は別途必要です。

## iOSヘルスケア連携

運動記録画面でもワークアウトの読み取り許可を要求し、過去90日間の最新20件から選んで取り込めます。運動の種類・開始日時・実運動時間（秒から分に換算）を反映し、重量・回数・セット数・疲労度は手入力します。同じワークアウトIDの重複保存は防止します。消費カロリー・距離は今回の取り込み対象外です。権限説明文を更新しているため、既存の開発ビルドは再ビルドしてください。

実機ではApple Watchなどで保存したワークアウトの取得、種類・日時・時間の反映、編集・保存、重複保存の防止、読み取り拒否・データなし時の案内を確認してください。

体組成の記録画面で「ヘルスケアのデータを取得」を押し、体重・体脂肪率の読み取りを許可します。過去90日間の最新20件の体重から選択し、入力内容を確認して保存できます。同じ取得元・測定時刻の体脂肪率だけを組み合わせます。筋肉量は手入力です。

サーバー通信、バックグラウンド同期、HealthKitへの書き込みはありません。記録は既存のアプリ内stateに保持され、アプリ終了で消えます。元のHealthKitデータは変更しません。

Expo Goでは利用できません。Windowsからは、ExpoとApple DeveloperのアカウントでEASを設定し、実機用開発ビルドを作成してください。`ios.bundleIdentifier`は自身のアプリIDに設定します。

```sh
npx eas-cli@latest build:configure
npx eas-cli@latest build --platform ios --profile development
npx expo start --dev-client
```



実機確認: ヘルスケアに体重・体脂肪率を登録し、初回許可、選択後の値と日時、保存と重複防止、読み取り拒否時の空表示を確認します。HealthKitでは読み取り拒否とデータなしを判別できないため、アプリは未取得を「連携済み」と表示しません。
